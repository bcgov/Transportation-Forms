

## Epic: Form Creation and Numbering Workflow

### Business Goal

Enable the Forms Team to **create form number reservation requests**, **reserve unique form numbers** (sequential by prefix), **enter special numbers** (manual with suffixes), and route the request through an **internal approval workflow**.

### In Scope

*   Sequential form number reservation by prefix (system-generated next number)
*   Manual “special” form number entry including suffix variations
*   When submitting special form number request, the user must also provide an explanation of why they need a special form number.
*   Reservation persisted and tied to a request
*   Internal approval routing to 1+ staff
*   Audit trail and access control (Forms Team handles assignment and approvals)

### Out of Scope (explicit)

*   Introducing any new libraries or technologies.

***

## Roles & Permissions

*   **Staff (Forms Team member)**  
    Can create a form request, reserve a generated number, or enter a special number, submit for approval.
*   **Approver (Forms Team staff)**  
    Can approve/reject, request changes, and finalize assignment.
*   **Admin**  
    Can configure prefixes, sequence formats, release unused form number, padding, allowed suffix patterns etc.

***

## Definitions / Data Rules

### Prefix-based sequential numbering

*   Prefix examples: `H`, `CVSE`, `INS`etc.
*   Each prefix has its **own independent sequence**.
*   System generates the **next available number** for that prefix.
*   Numbers are formatted with **zero padding** if required (e.g., `H0020`).

### Special form number pattern (manual)

*   Used for scenarios such as development approvals
*   Examples: `H0020A`, `H0020AB`, etc.
*   Special number includes **alpha suffix(es)**.
*   Must be **unique** across all reserved/assigned numbers for that prefix (and ideally globally).


### Reservation

*   “Reserved” means the number is **locked** to the request and cannot be requested again until released.
*   Reservation happens before approvals.
*   Reservation should be **atomic** (no duplicates under concurrent use).
*   Reservation should create an **audit event**.
*   Reserved number can be released by the request staff member or the Approver or the admin if not needed anymore.

> **Important open decision:** Reservation expiry/cancellation rules. See “Open Questions”.

# User Story 0 — Choose between auto-generated sequential number vs special form number

### Story

**As a staff form requester,** I want to select a prefix from a dropdown and choose **Form Numbering Method** from the two options - **Auto-generated number** and **Custom number** options, **so that** I can see the relevant options available to me.

### Acceptance Criteria

1.  **Prefix selection**
    *   **Given** I am a Forms Team requester  
        **When** I start a new form request  
        **Then** I can select a form prefix from a dropdown list (e.g., `H`, `CVSE`, …) and `Form Numbering Method` option to choose between `Auto-generated Number` and `Custom Form Number`

2.  **Form Numbering Method - Auto-generated number**
    *   **Given** I selected prefix `H`  
        **When** I click `Auto-generated number` 
        **Then** the system displays a read-only textbox with a button `Generate Number`.

3.  **Numbering option - Custom number**
    *   **Given** I selected prefix `H`  
        **When** I click `Custom Number` 
        **Then** the system displays an editable textbox that allows me to enter alphanumeric characters.

4.  **Custom Number - Explanation**
    *   **Given** I selected prefix `H`  
        **When** I click `Custom number` 
        **Then** the system displays a multiline text field to enter the reason why a custom form number is needed.

5.  **Switch Between Form Numbering Method**
    *   **Given** two numbering options are available  
        **When** I change my selection from `Auto-generated number` to `Custom number` or vice-versa
        **Then** the system clears out all the fields except prefix field to start afresh.


# User Story 1 — Reserve Next Sequential Form Number

### Story

**As a staff form requester,** I want to select a prefix from a dropdown and reserve the next sequential form number generated by the system, **so that** I can ensure a unique number is reserved early and proceed with the form request.

### Acceptance Criteria

1.  **Prefix selection**
    *   **Given** I am a Forms Team requester  
        **When** I select `Auto-generated number` from the `Form Numbering Method` options
        **Then** I can see the fields available to me

2.  **Next number generation**
    *   **Given** I selected prefix `H`  
        **When** I click `Generate number`  
        **Then** the system generates the next sequential number for `H` according to its configured format (e.g., `H0021`).

3.  **Uniqueness & atomicity**
    *   **Given** two users attempt to reserve the next number for the same prefix at the same time  
        **When** both click Generate number”  
        **Then** the system reserves **two different** sequential numbers with no duplicates.

4.  **Reservation persistence**
    *   **Given** a number is generated  
        **When** the user clicks `Submit Request` 
        **Then** the number and the combination of number with Prefix value is saved and tied to the form request with status `Pending Approval`.

5.  **Error handling**
    *   **Given** the prefix configuration is missing or sequence cannot be advanced  
        **When** I attempt to reserve a number  
        **Then** I see an actionable error message and the request remains without a reserved number.

6.  **Audit trail**
    *   **Given** a reservation is made  
        **When** the reservation completes  
        **Then** the system logs: timestamp, user, prefix, reserved number, request id, and action type `RESERVE_NUMBER`.

# User Story 2 — Enter and Reserve a Special Form Number (Manual)

### Story

**As a staff form requester,** I want to manually enter a **Custom number** (including optional suffix letters), **so that** I can reserve numbers like `0020A` for special scenarios.

### Acceptance Criteria

1.  **Manual entry option**
    *   **Given** I am creating a new form number reservation request  
        **When** I choose `Custom number`  
        **Then** I can enter a full form number including suffixes (e.g., `0020A`).

2.  **Validation: required components**
    *   **Given** I enter a manual number (alphanumeric) 
        **When** I attempt to reserve it  
        **Then** the system validates it contains:
        *   alphenumeric characters within the up to the max length set in the configuration (e.g., 3, 5)
        *   The combination of prefix and custom form number entered is unique in the database

5.  **Uniqueness**
    *   **Given** `H0020A` is already reserved or assigned  
        **When** I try to reserve `H0020A` again  
        **Then** the system blocks it with a clear message and does not reserve.

5.  **Sequence impact (no forced increment)**
    *   **Given** I reserve a manual number that is outside or behind the current sequence  
        **When** the reservation completes  
        **Then** it does not break sequential reservations; future “next number” generation continues from the configured sequence counter.  
        *(This preserves sequential integrity.)*

7.  **Audit trail**
    *   **Given** a manual reservation occurs  
        **When** it is saved  
        **Then** an audit record is created with action `RESERVE_SPECIAL_NUMBER` including the entered value.

# User Story 3 — Route Reserved Form Request for Internal Approval (1+ approvers)

### Story

**As a staff form requester,** once a form number is reserved, I want to submit the request for **internal approval by one or more staff members**, **so that** the form request is reviewed and approved before finalization.

### Acceptance Criteria

1.  **Submit for approval**
    *   **Given** I have entered all the required fields  
        **When** I click “Submit Request”  
        **Then** the request status becomes `Pending Approval`.

2.  **Approver assignment (1+)**
    *   **Given** the workflow requires approvers  
        **When** I submit  
        **Then** the system routes it to **one or more** designated approvers (based on configuration, role/group membership).

3.  **Approver actions**
    *   **Given** I am an approver  
        **When** I open a pending request  
        **Then** I can:
        *   Approve (status → `Approved`)
        *   Reject (status → `Rejected`, with mandatory reason)
        *   Request changes (status → `Changes Requested`, with comments)

4.  **Reservation integrity during approval**
    *   **Given** the request is `Pending Approval`  
        **When** anyone attempts to reserve the same number on another request  
        **Then** the system prevents it (reserved number remains locked).

5.  **Notifications (if applicable)**
    *   **Given** a request transitions statuses  
        **When** it is submitted/approved/rejected  
        **Then** the requester and approvers receive notifications (in-app) as configured.

6.  **Audit**
    *   **Given** an approval decision is made  
        **When** the decision is saved  
        **Then** audit logs capture approver, timestamp, decision, comments.

***

## Suggested Status Model (for developer clarity)

*   `Reserved` → number reserved (system/manual)
*   `Pending Approval` → routed to approvers
*   `Changes Requested` → returned to requester
*   `Approved` → approved internally
*   `Rejected` → rejected internally

# Testing Procedure

## A) Automated Test Recommendations

### Unit Tests

*   Sequence generator increments correctly per prefix
*   Manual number parsing/validation (prefix, numeric part, suffix rules)
*   Uniqueness constraint behavior

### Integration Tests

*   Reservation endpoint is atomic under concurrent requests (use parallel test runner)
*   Workflow status transitions enforce rules (cannot submit without reserved number)
*   Role-based authorization checks at API level

### Database Constraints (strongly recommended)

*   Unique index on `form_number` (or `(prefix, numeric, suffix)` normalized)
*   Transactional reservation method using row-level locking or sequence table per prefix
